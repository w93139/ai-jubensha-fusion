## 文字试玩执行边界（4B／4D）

从开场显式创建独立 `play-…` 会话并重核发布，绑定所属用户、角色、包版本、模型配置与费率。当前 API 和 schema 以[文字试玩协议](package-play.md)为准：真人手动 ADVANCE_PHASE/SHARE_MATERIAL，到末阶段显式 SETTLE，之后禁止新动作。SETTLE 只返回 `settlement.instructions.text` 与 `truth_ids` 引用的真相，不从说明文字推断胜负、投票或凶手判定。

1.2 另支持真人显式 PERFORM_ACTION，仅提交 action_id、revision 和幂等键。服务器核验阶段、角色、全部前置与余额，同一事务扣点、完成动作及授予材料；同一动作全局最多成功一次，零成本也不例外。每阶段调查点独立、不结转，按包声明的 ALLOW_REMAINING/REQUIRE_EXHAUSTED 限制推进及终末 SETTLE。页面只返回当前允许且付得起的动作，不返回隐藏原因、奖励目标或未解锁正文。调查点与 AI Token/人民币预算分别记账，AI 不执行调查动作。

目标 AI 的输入只含本人身份、当前阶段、当前公开材料与本人已解锁且可分享的 MAY_SHARE/MUST_SHARE；KEEP_PRIVATE、他人私本、未解锁材料、真相、结尾和来源不进入输入。模型只返回受限 refs，服务核验后将选中私有材料正式公开、触发确定性条件解锁，并以原文组成答复；无引用时返回固定答复。事实、角色说法与推测分类保留。

各角色共用本局预算。AI_REQUEST 在事务内持久化与预占后才单次调用模型，等待时不持有事务/锁；AI_RESULT 复核版本、阶段 revision、租约、配置及当前发布，过期/失效结果只记用量，不分享或发言。SDK 与应用不自动重试，未知用量按预占保守入账，同键不再调用模型；无自动跨供应商回退。该严格 revision 规则不沿用下文旧 Fusion 的普通聊天兼容设想。

页面只响应显式点击，GET 恢复已有会话。AI 配置或预算不可用不妨碍手动操作，但推进和揭晓仍须满足包的前置与调查预算门槛。结构可达性检查不证明每个真人选角、每种动作顺序均能完成，内容审核须独立检查，不能假设 AI 代搜证。调查机制和未知奖励不进入角色模型输入。网络失败重试保留原请求，明确进度冲突须先刷新，再由用户显式重试。仅服务明确的 revision 冲突允许保留 key/问题并更新 revision，其余冲突不得据此改写请求。

## 身份与权限（完整运行设计目标）

一个角色 Agent 是“同一适配器代码 + 本局该角色的独立输入”，不是全知模型换一个角色名字。

| 范围字段 | 权威来源 | 约束 |
| --- | --- | --- |
| `user_id` / `session_id` | 服务端认证与会话成员关系 | 不相信模型或请求正文自报身份；读取和写入均检查对象归属 |
| `script_id` / `script_version` | 会话绑定的发布版本 | 不能跨本检索；新包开场、演练与 4B 文字试玩已有不可变绑定，旧游戏不回填；4B AI 消费独立会话固定权限 |
| `character_id` | 服务端分配的参与者关系 | 不能通过换角色 ID 读取其他私本 |
| `phase` / `state_version` | 规则服务与持久状态 | 模型不能自报进入下一阶段或解锁新知识 |

模型不得获得数据库连接、Shell、任意文件读取、全本 RAG 或发布权限。后台 Compiler/Audit 的素材访问与游戏角色视角分离；后台全本检查结果不能直接成为玩家上下文。

## 动作契约（设计目标）

现有动作包括 `select_character`、`ready`、`advance_phase`、`send_message`、`ask_question`、`search_location`、`reveal_evidence`、`cast_vote`，不是任意工具执行入口。

每个动作须登记：参数 schema、允许阶段、对象权限、状态前提、副作用、幂等范围、对外错误类别。新增动作必须同时补规则、服务端授权和测试；模型只能提出候选，不能宣布动作已经成功。

执行顺序：认证 → 会话/角色归属 → 请求校验与幂等核对 → 阶段/资源/条件校验 → 事务内状态及事件写入 → 授权后的响应。

- 同一幂等键与同一请求返回既有结果；同键不同参数拒绝。客户端不能占用内部 AI 键。
- 非法动作不扣资源、不推进阶段、不生成可见成功事件。
- 事件只由服务端确认；角色台词“我搜到了”不构成已获得线索。
- 模型等待期间不长期占用数据库写锁；返回后复核原动作依赖的会话、角色、阶段及版本。
- `state_version` 用于顺序和一致性判断，但不能机械地使每条普通聊天都撤销仍合法的在途发言。

上述为旧 Fusion 与完整运行设计边界，不把它们当作 4B/4D 任意动作扩展；文字试玩的严格动作及重试规则以本页专节和独立协议为准。隔离并发证据只覆盖已测试场景，不代表全部生产故障均已验收。

## 角色上下文与记忆（设计目标）

只组合：该阶段已解锁的本人材料、已获线索、可见事件、相关的角色记忆。事实条目带来源与可见范围；对他人陈述保留说话者，对角色推测标记不确定性，不把推测写回权威事实。

授权投影 → 窗口裁剪 → 必要时摘要 → 模型输入。顺序不可反转。

- 摘要绑定局、剧本版本、角色、事件游标与来源；它是可重建缓存，不是授权凭据。
- 摘要不能重新读回已过滤的秘密、宿主真相或其他角色私有事件；失效时从有权限的原事件重建。
- 原文/OCR/RAG 命中及玩家消息都是数据，不能修改工具权限、提示层级或游戏规则。
- 若以后接检索，检索前按本局、剧本版本、角色、解锁条件过滤；命中后再复核，不把全本结果交给模型自行保密。
- 知道某条事实不等于可以公开；披露策略由结构化规则表示，不能只靠提示“不要自爆”。阶段 4A 对新包实现阶段下限、公开证据 AND 条件和本人显式分享；4B 已接入 AI 本人可分享资料的受限选择与服务端正式分享，完整自然对白、主持与商业结算仍须另行定义。

## 旧 Fusion 输出、超时与费用

旧 Fusion 的发言输出是严格对象：`{"message": "角色台词", "action": "speak"}`，拒绝额外字段、空白台词、超长内容和内部思考标签；有界重试后降级。**这仅证明格式合规，不证明语义无剧透。**

- 当前 Fusion 角色运行明确记录提供方、模型/Endpoint 指纹、配置版本、Prompt 哈希、超时、重试和思考参数；默认角色对白为火山方舟 `doubao-seed-character-260628`，百炼固定版 `qwen3.7-flash-2026-07-15` 只作显式手动备用和未来 GM 总结候选。
- 每局冻结一家 provider；失败、拦截或超额只做安全降级，不能自动跨供应商重发同一份角色上下文。当前没有已验收的 GM 模型链路。
- 当前费用控制区分输入、缓存输入、输出和重试；并发请求在持久收据中先预留额度，返回后结算，未知计费按最大预留暂记并允许迟到对账。
- 每局在首次模型动作时冻结模型与价格配置；费用上限、费率或价格版本缺失时，付费调用失败关闭。
- 当前可区分取消、过期、迟到、格式失败、预算不足和未知用量；异常原文或 SDK 调试信息不作为台词。
- 这些能力已有 SQLite/mock 证据，但 PostgreSQL 多进程争用与真实供应商账单仍待验收；`estimated_cost` 仍是兼容旧库的 Float 汇总值。
- TTS 仍为候选，不视为运行时已接通；不得假设文本平台的 key、接口与语音平台通用。

## 观测与验收（设计目标）

观测日志默认仅记录调用 ID、角色范围标识、动作/阶段、结果类别、耗时、用量和版本，不写密钥或私本正文。游戏事件可以保存授权玩法所需内容，但必须经过对象权限投影后才对外展示；它不是公共调试日志。

| 编号 | 最小失败用例 |
| --- | --- |
| RT-01 | 另一局/另一角色/另一剧本的 ID 不能扩大输入范围；未知可见性拒绝 |
| RT-02 | 未知动作、阶段不匹配、未拥有线索的公开请求均不产生副作用 |
| RT-03 | 同键重放不重复执行；同键变更参数拒绝；旧阶段模型结果不落成新台词 |
| RT-04 | 一个角色修改输入副本不影响其他角色；压缩不能增加知识或改变来源性质 |
| RT-05 | 非法 JSON、思考标签、截断、模型不匹配、超时与取消不泄露内部输出；旧 Fusion 仅对暂时性传输／服务故障有限重试；4B 不自动重试，非法输出不重发 |
| RT-06 | 未解锁事实不出现在私本/提示/检索/摘要中；允许公开的事实不会被永久拒绝披露 |
| RT-07 | 并发费用预留与调查扣点不超限；异常用量可追踪；离线测试不调用真实模型，隔离 PostgreSQL 与真实模型另行留证 |

RT-06 的通用阶段/披露与行动奖励已在 4A、4B、4D 接线，商业本专属机制和完整 AI 语义仍待验收。RT-07 已有 4C 真实角色材料选择和 4D 隔离 PostgreSQL 11 项证据，包括争抢最后一点与同键不重复；不能将其替代尚未通过的新 1.2 真实 Compiler/Audit 链、生产恢复或供应商账单验收。文件授权、发布绑定、浏览器恢复与并发分别按各阶段实际用例记录。
