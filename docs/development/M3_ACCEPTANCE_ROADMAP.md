## M4 如何展开

建议先选择一个与唐小姐在回忆/动机/信息披露上差异较大的角色作为首个扩展，再覆盖其余角色；具体顺序依来源核对结果安排，不把此建议当已确认排期。

1. **角色适配表**：逐角色核对开场资料、阶段目标、必须讲/可隐瞒/未知、回忆触发、合法交流对象、答卷与评分依据。案件事实和原角色信念保持，不能把别人说法升级为真相。
2. **运行与界面**：绑定所选真人并让其余四席作为 AI；把当前唐小姐专用引导推广为各角色对应内容，标题和问题按阶段与已得材料开放。仅开放选择按钮不算角色适配完成。
3. **离线与恢复**：每种选角检查调查顺序、回忆链、提前结束/错误判断、预算边界、未知请求、封卷和刷新；验证新旧局独立，旧局不换角色、不自动升级。
4. **受限真实整局**：逐角色保留模型回复与有源语义复核、必需信息送达、卡住路径、五席结算和实际费用；失败/固定答复与成功模型分别统计，不无限重发。
5. **玩家试玩**：交付五份简短角色操作单和逐角色问题清单，让用户确认目标是否清楚、角色表现是否成立、调查及判断是否有意义。各角色达到退出标准后汇总第一版验收。

## 持续开发的固定流程

1. **记录反馈与状态**：写清玩家操作、预期/实际、影响范围；标明用户已认可部分和剩余问题。
2. **核对来源与现有实现**：先查当前 PRD、交付记录、冻结内容和运行规则，区分原文事实、适配规则、推断与建议。
3. **形成可检验的小任务**：列可见交付、验收标准、修改范围和风险；原权限、账本与旧局兼容必须明确。
4. **实现与离线检查**：针对本次行为做测试、类型/lint/必要安全检查；有独立只读复核时及时处理 Blocker/Important。测试不采用商业全文。
5. **按需要做真实验证**：界面用实际页面和相关尺寸操作；模型/语音仅做已授权、费用受控的必要样本。保存原请求和失败，不把模拟结果记为真实成功。
6. **发布本机候选与存储版本**：先保护和核对旧数据，再验证更新后的页面；验证后的后端版本按既有授权同步私有 GitHub 普通提交和新标签并核对远端。商业材料、密钥、音频、存档和模型日志不进代码备份。GitHub 备份不等于正式产品发布。
7. **交付给用户**：提供入口、实际变化、操作方法、标准、未测/失败，以及下一轮所属阶段、具体工作和建议思考强度。不要只报测试数量或虚假完成百分比。
8. **修复并退出阶段**：按原问题复验，不重复从头验全部已认可内容；汇总退出标准后再推进里程碑。正式内容发布仍遵守独立人工确认门禁。
