## 1. 产品形态判断

- 产品类型与核心任务：一名真人和多名彼此隔离的 AI 角色，按固定阶段完成一整局剧本杀。
- 核心交互：多轮对话、分阶段确认、搜证、分享或解释、投票与结算；模型不能自由调用任意工具。
- 权责边界：服务器决定阶段、线索权限、行动是否合法、投票和结局；模型只生成角色候选发言，不能自行修改游戏状态。
- 开发路径：采用“纵向切片”。项目已有 `/play` 页面和 `/api/fusion` 游戏接口，后续沿这条真实链路逐步完善，不另造一套临时产品。
- 第一阶段范围：模型接入、思考内容隔离、调用前预算预占、失败或迟到对账，以及相互独立的离线、PostgreSQL 和真实模型技术验证。
- 第一阶段当时不做：商业正文导入、剧本改写、版本化剧本包、Compiler/Audit、人审发布、具体剧本规则、TTS/ASR 和上线部署；后续包与发布进展见本页顶部。
- 材料边界：已定位到用户授权的私有材料，足够开始第一阶段的纯技术开发；这不代表材料已完成内容审核、能够完整导入或已经可以整局游玩。精确盘点与校验记录只保存在 Git 外的私有目录。

## 2. 采用的默认方案

- 后端继续使用现有 FastAPI、Pydantic、SQLAlchemy、PostgreSQL 和 Alembic。
- 前端继续使用现有 Next.js、React 和 TypeScript；本阶段不重做视觉界面。
- 第一阶段默认角色对白渠道为火山方舟，模型 `doubao-seed-character-260628`；阿里百炼固定版 `qwen3.7-flash-2026-07-15` 已纳入显式手动备用，并保留为未来 GM 总结候选。当前不存在已验收的 GM 模型链路。
- 每局只冻结一家 provider。供应商失败、内容安全拦截或额度不足时安全降级，不自动把同一份内容转发到另一家。
- 普通实时对白在代码中固定为非思考模式，不能通过环境变量打开；未来 GM 若需思考，必须另建受控任务契约和输出预算。
- Prompt 使用文件内容哈希作为版本号；每次模型运行只记录脱敏配置、额度和状态，不记录密钥、私本正文或内部思考。
- 规则、权限、预算和发布继续由确定性代码执行，模型输出先做严格结构校验。
- 先做无网络 mock 测试；独立 PostgreSQL 并发验证和真实模型冒烟分别留证。

## 3. 触发的按需模块

- WebSocket：由多轮互动触发；复用已有实现，本阶段不增加 SSE。
- 持久化调用收据：由并发 AI 发言、预算预占、重试与对账触发；本阶段引入。
- 租约与恢复：由中断、超时和进程异常触发；本阶段引入。无法确认供应商用量时按保守上限暂记，不能当成免费。
- 来源追踪与导入白名单：由商业材料触发；第二阶段才实现。
- OCR、RAG、对象存储、TTS、ASR 和正式发布工作流：本阶段不引入。

- Python 3.11 默认方案：替代为仓库锁定的 Python 3.13；原因是现有依赖已按 3.13 锁定；影响是不能直接照抄 3.11 环境命令；只有仓库依赖整体升级且迁移测试通过时才重新评估。

- `/api/v1` 默认前缀：继续使用 `/api/fusion`；原因是前端和既有契约已经依赖该路径；影响是新文档与测试都须沿用现有路径；只有安排了客户端兼容迁移时才重新评估。
