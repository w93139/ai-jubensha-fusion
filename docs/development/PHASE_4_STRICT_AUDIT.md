## 已确认的问题和实现

原审核 schema 是 `{"output": schema}`，提示却要求报告直接位于顶层、不包裹 output/report。JSON Schema 验证器会把未知的 output 关键字忽略，因此这个包装不是有效的顶层约束。这是已验证的输入契约缺陷；4I 没有保存被拒绝原文，不能据此反推它当时究竟错在哪个字段。

本轮保留同一个模型、来源、准备稿、提示正文及质量标准，使用四个显式新版本分别记录结果，不升级或重发历史任务：

| 请求/模型版本 | 新模式 | 变化 |
| --- | --- | --- |
| 1.7 | DIRECT_BOUNDED_SOURCE_INDEXES | 直接传入顶层审核 schema |
| 1.8 | STRICT_BOUNDED_SOURCE_INDEXES | Audit 使用供应商 json_schema + strict；Compiler 保持 json_object |
| 1.9 | PORTABLE_STRICT_SOURCE_INDEXES | 提供包含整串匹配的非空白正则，保留本地校验 |
| 1.10 | TYPED_STRICT_SOURCE_INDEXES | 仅从供应商生成 schema 去掉 pattern；本地仍执行全部原校验 |

[百炼官方结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)列出 Qwen3.7-Flash 系列的 JSON Schema 支持。新 response_format 冻结进任务请求契约和哈希，其 UTF-8 字节也计入保守输入预算；持久任务会核对版本及完整格式，不能降级成 json_object 后继续。4096 输出上限和原预算保护保留，非 stop 仍拒绝；官方对结构化输出不建议截断的提醒不构成移除本项目费用上限的授权。

1.8 出现单字说明后，离线验证了 `\S` 的 JSON Schema 搜索语义和整串匹配语义不同；这只是供应商正则兼容问题的假设，不是其内部实现的已证实根因。1.9 的等价非空白表达没有解决真实输出问题。1.10 只把正则留给本地执行，供应商仍约束类型、枚举、必填字段、禁止额外字段、长度/数量和数字边界。没有默认补字段、删发现或放宽最终接收标准。

请求版本、工作台、worker、预算和失败诊断的契约见[严格审核](../contracts/strict-audit.md)。工作台“固定规则和正文，只检查内容”新任务使用 1.10；历史 1.0–1.9 保持原快照。提示中的 schema 和供应商 schema 可以按该显式版本不同，两者都冻结并计入预算，不能混用。

## 1.10 意见的独立只读复核

原报告不改写，烟测不改为通过，以下工程核对不是人工处理记录：

1. AI 称结尾 truth_ids 为空；实际候选为 `["truth"]`。原烟测验证了精确真相映射，并对两种真人选角分别实际执行结尾揭晓。
2. AI 称缺少 per_game_limit；当前引擎全局记录成功动作，同一动作整局最多一次，免费动作也适用。这是程序固定规则，不是候选缺失字段。
3. AI 假设甲先耗尽 3 点后还需乙执行调查；当前单真人流程仅所选角色可调查。原烟测对两种真人选角分别完成耗尽点数、推进和结尾。AI 分享获准材料是另一种操作，不消耗调查点。

这只能反驳该固定样本中的具体假设，不能证明商业本全部选角、行动顺序或任意材料语义都正确。严格 JSON 输出同样不能保证模型意见真实、充分、无遗漏。

为方便实际核对，管理员只读对照接口新增 `rule-review/1.1`，展示当前引擎的单真人、一次动作、共享且不结转点数、私有材料按声明归属发放，以及候选实际的结尾 truth_ids 和结尾来源。前端兼容旧 1.0，未知规则事实拒绝显示。新接口重新核验来源但不写文件、候选或人审；这些事实未偷偷加入旧模型快照或玩家视图。
