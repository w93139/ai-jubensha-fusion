# 阶段 4M：只选择现有引用的离线原型

2026-09-06。针对 4L 中目标/来源编号装配失败的可能出错面，完成另一种输出格式的离线可行性验证：模型只填写已有引用目录中的索引，目标和来源由服务器确定。它不是对 4L 原始错误值的还原，也未证明能够改善真实模型输出。

本轮新增纯本地 schema、目录生成和装配器，**没有接入 Authoring 任务、worker、付费工具或工作台**。现有流程仍为 1.11，历史请求、提示、候选和收据保持。此原型没有供应商调用入口，`dispatch_enabled=false`、`provider_compatibility=UNVERIFIED`；不把文件存在当作已上线能力。

## 为什么先分开验证

旧格式需要模型同时填写自由文本目标 ID 和该目标内部的来源编号，二者都可能出错。新原型将每一项“目标＋它自身的一处引用”编为一个目录项。模型无需生成目标 ID、source_id、anchor、page 或发现 ID；服务器仅依据所选目录项装配，不猜测、不补来源。

每条发现保留 category、severity、message 和非空 citation_indexes。一个发现可选同一目标的多处来源，严格按所选顺序保留；即使两个目标恰好引用同一段原文，也不允许在一条发现中混用不同目标的目录项。发现 ID 根据报告顺序生成，它只是记录标签，不是新造的候选或来源 ID。

摘要上限 240 字符、说明 160 字符、发现最多 10 项、每项引用最多 100 个，五维覆盖及 COMPLETE/INCOMPLETE 规则保留。重复/空/非整数/越界索引、空白说明、额外字段或未完成状态均拒绝，最终仍经过原 `validate_model_audit` 完整领域校验。BLOCKER 原样保留，零发现也不代表人审批准。

目录最多 2048 项，先计数再复制，超限直接拒绝，不截断或遗漏目标。目录顺序与旧目标目录一致，package_hash 与 catalog_hash 一起绑定解释依据；候选顺序或来源变化后，旧索引不能继续解释为新内容。

本地生成的 schema 将引用上界收窄到本目录最后一项；供应商候选 schema 仅去掉 pattern，本地正则及其他约束仍完整执行。跨目标和去重仍须本地验证，JSON Schema 有效不证明所有业务条件成立。供应商是否接受并稳定遵守该动态 schema 尚未验证。

新增 25 项离线检查，包含多来源选择保留、相同原文但不同目标的混用拒绝、动态索引范围、目录变更绑定、容量拒绝，以及完整性/空白/重复/越界/非法类型和 BLOCKER 边界。
