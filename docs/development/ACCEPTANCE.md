## 四类证据必须分开

| 层级 | 要证明什么 | 不代表什么 |
|---|---|---|
| 离线 | mock模型、虚构数据、规则/权限/格式/前端组件通过 | 真实PostgreSQL并发、模型剧情质量或实际时延 |
| 数据库集成 | 隔离测试库的迁移、事务、锁、幂等、恢复通过 | 已导入真实本或已可对外发布 |
| 模型与语音 | 授权样例的角色质量、费用、首音/完整时延、降级通过 | 所有剧本都正确或永不幻觉 |
| 剧本整局 | 冻结版本按原规则，从入场到结算可复现完成 | 仅页面能打开或AI说“结束了” |

## 必须覆盖的失败场景

- [ ] 错误session/script/version/character的事件、检索、线索访问均被拒绝。
- [ ] 角色尚不自知或尚未回忆的信息，不因background/secret/凶手标签提前透露。
- [ ] 模型发出非法动作、未知枚举、夹带指令或伪造来源，服务器不执行。
- [ ] 线索按阶段/条件/权限逐项获得，不一口气发出全阶段内容。
- [ ] 必须分享的信息在规则时点分享；允许隐瞒的信息不被强行公开。
- [ ] 被证据质疑时只基于本人已知事实解释，不编造新的不在场证明。
- [ ] 压缩/重连/检索不扩大知识范围；他人说法与客观事实分开存储。
- [ ] 提示分级且由批准的提示集合产生，不直接输出答案。
- [ ] 重试/并发/崩溃不重复计入游戏动作；已发生但用量未知的请求进入对账。（离线与真实并发已有部分证据，崩溃/重启仍未完成，故不勾选。）
- [ ] 源文件/包/规则版本变化，使下游校验、Audit和人工批准失效。
- [ ] 校验失败、无来源、Audit阻断项未处理、无对应版本人审，均不能PUBLISHED。
- [ ] 导入事务失败不留下半本；历史运行绑定不可变版本。
- [ ] 文本与音频输出都经过可见性检查；内部思考不交给TTS。
- [ ] 打断/取消/跨阶段后过期音频不再播放，恢复后事件序号单调。
- [ ] 日志与错误信息无密钥、跨角色私密正文、完整商业素材。
- [ ] 发布版修改和文件下载具备对象授权与版本保护。
