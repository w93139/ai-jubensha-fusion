# 阶段 4A：固定角色阶段演练

状态：本轮代码、离线验证、生产构建与隔离浏览器验收完成，2026-09-06。承接[阶段 3D](PHASE_3_PUBLICATION_BINDING.md)，已完成确定性的阶段推进、本人资料公开和条件解锁，再接后续 AI 角色互动。用户指示继续开发，当前没有需要用户补充或先试玩的信息。

## 本轮适配与边界

沿用现有 FastAPI、SQLAlchemy、Next.js 与候选包 v1/v1.1，不增加平台、依赖或费用。用户当前打开的素材目录内技术手册与 `agent-blueprint` 中手册字节哈希相同，继续采用已确认的纵向切片开发方式。本轮使用虚构资料、离线测试和回环浏览器夹具，不处理商业正文、不调用真实模型、不修改 `.env`、不迁移用户数据库、不部署。

当前包只有线性阶段、阶段下限、公开证据 AND 前置条件和披露策略；没有主持权限、搜证资源、计时、投票机制或阶段完成条件。因此本轮称为 **阶段演练**：人工点击后按 `next_phase_id` 查看下一阶段，只验证既有字段的确定性含义，不把它宣称为完整剧本游戏。

`MUST_SHARE` 没有披露截止时点，不能据此自行增加自动公开或禁止进入下一阶段的规则。本轮提供本人已解锁材料的显式公开，保留“按规则需分享”提示；`KEEP_PRIVATE` 永不允许公开。其他角色不代为行动，其私密证据不因某条依赖需要它就被自动公开。到最后阶段仍不返回后台真相、结算指令或胜负；完整主持与结算授权留到后续工作包。

## 独立会话与授权

保留旧开场 `package-opening-preview/1.0` 不可变绑定和无动作接口。用户在已有开场点击“检查后续阶段”，再显式创建新的 `package-flow`，重新验证当前发布有效。每份开场最多一份演练；刷新或重进恢复同一演练，不静默把旧开场升级。

演练固定 owner、开场、发布记录、候选版本/哈希、角色与引擎契约。读取历史演练保留已获得材料；新的权限扩张动作要求当前批准仍有效。审核变化后新动作停止，旧开场不会因此得到后文。幂等重放只返回原动作当时的授权结果，不重复推进，也不在重试时借最新状态增加权限。

保存不可变演练绑定及逐条动作记录，动作绑定请求哈希、序号、前一事件和结果状态哈希；读取验证整个历史并确定性重演。数据库候选锁先于演练锁，来源核验在持锁之前，SQLite 真正开始写事务后才能开保存点。异常、旧 revision、同键不同请求或越权不留下半条动作。

## 确定性规则

- 阶段顺序从初始阶段沿下一阶段连接取得，不使用数组顺序；客户端不能指定跳转目标。
- 材料达到阶段下限且全部前置证据已公开后解锁。本人已知、角色说法或模型台词不算证据已经公开。
- 原生 PUBLIC 证据按依赖计算连续解锁结果，再判断知识材料；晚到的条件仍可解锁较早阶段材料。
- 只有本人已解锁的 `MAY_SHARE`、`MUST_SHARE` 可以公开；知识与证据的目标包含集合名称，避免同名 ID 混用。公开知识不能满足证据依赖。
- 玩家视图仅含已解锁公开资料及本人私密资料，保留 FACT、CLAIM、INFERENCE 和披露规则，不返回来源、后台真相、其他私密或未解锁目标。

## 接口与验收

新增 `/play/package-flow` 最小操作页与 `/api/fusion/package-flows` 创建/查找、`/{flow_id}` 读取、`/{flow_id}/actions` 动作接口。结果标明 `status=RULES_PREVIEW`、`runtime_ready=false`。动作仅 `ADVANCE_PHASE`、`SHARE_MATERIAL`，严格请求带幂等键及 `expected_revision`。不连接旧游戏动作、自由指令或模型工具。

必须验证：不同阶段/角色/局/版本隔离，AND 和连续解锁，私有证据不算公开，KEEP_PRIVATE 拒绝，MUST_SHARE 不自动公开，同集合与跨集合 ID，阶段末端不泄密，刷新重读、版本冲突、重复请求、事务回滚、已缓存对象时的篡改拒绝、发布失效后只读保留。迁移只在隔离 SQLite 上下行及 PostgreSQL 离线 SQL 中验证；真实多进程与恢复不能由此宣布通过。

操作验收使用新虚构夹具：开场 → 显式开始演练 → 公开本人证据 → 连续解锁 → 下一阶段 → 刷新保留，电脑与 390px 页面检查，确认无真实模型调用并清理临时服务。最终记录测试数量、证据位置和下一步；当前用户不必提前操作。

## 尚未覆盖与下一步

本轮不是商业剧本整局验收，未接入 AI 角色、主持、行动资源、投票、结算揭晓、语音或多人贡献。其他角色的私密前置不能由本角色代为满足，阶段末端不代表原本流程已完整实现。真实 PostgreSQL 多进程事务与恢复仍未验收；同库哈希链也不能检测拥有原始 SQL 权限者对全部末尾历史的整体回滚，需数据库权限和外部备份配合。

下一工作包为阶段 4B：把新包固定版本、角色、阶段和公开证据投影接给受限的 AI 互动，先用虚构包验证它只消费当时被授权的材料，并与已有单局预算及过期结果拒绝机制衔接。完成可重复的完整操作链后，再给用户简短的试玩步骤，不要求用户现在判断代码或审核格式。
