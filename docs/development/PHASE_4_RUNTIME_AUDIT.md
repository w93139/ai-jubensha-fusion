# 阶段 4K：版本化审核运行规则与反例

2026-09-06。针对 4J 的“空真相编号”“缺少动作次数限制”“多人轮流调查”误报，新增显式 1.11 审核模式。程序固定规则单独进入系统消息，候选结尾字段由服务器复制到观察区；规则不能由来源备注覆盖。新入口、持久任务、worker、工作台及离线反例已接通。本轮没有真实模型调用，不能声称误报率已经降低，没有人工批准或发布，`runtime_ready=false`。

## 修改及边界

旧提示已经提到单真人调查，真实模型仍理解错误。因此本轮不把“补一句提示”当作有效性证明：新增 `audit-runtime/1.0` 结构化规则，明确当前引擎的角色、动作、费用、奖励和结束语义，同时独立建立正常与失败样本。旧 1.10 及其提示和真实结果不变。

系统规则涵盖：只允许所选真人调查；动作整局最多成功一次，包含免费动作；全部动作和公开证据前置同时满足；阶段共享点数不结转；REQUIRE_EXHAUSTED 要求当前点数为零；私有材料归声明的角色；AI 材料分享与调查分开；显式终末操作只揭晓包指定的 truth_ids。它也明确未提供任意路径可达证明、完整票制评分、关键词回忆、复杂分支及节奏平衡验收。

`audit_runtime.py` 为审核系统消息和只读规则页提供同一组固定事实，规则页原 1.1 响应形状不变。`candidate_observations` 仅复制已通过原候选校验的结尾 phase_id、truth_ids，并绑定候选 hash；不复制真相正文，不读取预期答案，也不推导“正确结局”。候选实际真相编号改变时观察值随之改变；空 truth_ids 仍被原包校验拒绝。

新提示要求区分字段事实、来源矛盾、程序能力不足和未验证推测。程序只支持单真人，不代表来源要求 AI 调查时可以忽略能力差距；非空 truth_ids 也不能代替对答案、评分和分支的审核。模型仍可提出 BLOCKER，完整保留原人审发布门禁。没有“已提供运行规则就自动通过”的逻辑。

运行规则序列化进新系统提示，纳入 prompt hash、模型快照和请求契约 hash；消息及观察值的 UTF-8 字节计入原保守输入预算。更改已准备消息会在 SDK 创建前拒绝。客户端/来源不能新增同名顶层事实来替换程序规则，来源备注仍作为不可信数据传递。旧 Compiler 的提示正文、结构输出、完整冻结草案和原质量标准不变。

契约及显式参数见[运行规则审核接口](../contracts/runtime-audit.md)。新建固定规则与正文任务选择 1.11，老任务按旧版本重读；不自动升级、恢复或重发失败任务。

## 独立反例与模拟链

[语义验收样本](AUDIT_SEMANTIC_CASES.md)保留一组正常资料与两组故意破坏的候选。三组均通过结构/来源定位校验，但两组确实无法完成某些真人路线。测试实际调用确定性引擎，不让模型自证答案：

| 样本 | 真人甲 | 真人乙 |
| --- | --- | --- |
| baseline | 两次调查后点数为零，可推进并揭晓指定真相 | 同样可完成 |
| unspendable-budget | 两次调查后剩 1 点且无可用动作，推进被拒绝 | 同样卡住 |
| role-dead-end | 可完成 | 无权执行第二个动作，剩 2 点、无法推进 |

这些只证明记录的路线，不证明任意行动顺序或商业本完整体验。源文件一致性仍可能通过，因为它不能判定规则语义；反例保持这种区别。案例预期和执行轨迹存于单独文件，不进入模型消息。免费动作不可重做、AI 不可代花调查点，也有独立引擎检查。

模拟 SDK 的成功、不完整、长度结束、未知结束、超时、格式无效路径均验证 1.11 版本、持久化、计费账本和拒绝重试；另有完整格式但带 BLOCKER 的样本，确认任务可 COMPLETED 而烟测仍 FAILED，不会抹掉阻断意见。模拟结果不计作真实模型准确率。
