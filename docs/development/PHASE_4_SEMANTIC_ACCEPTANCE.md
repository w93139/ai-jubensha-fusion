# 阶段 4L：固定样本的真实审核验收

2026-09-06。沿用 4K 的 authoring-model/1.11、原提示及全部输出校验，新增独立的四样本 Audit 验收工具。本工具仅审核程序准备的虚构候选，不运行 Compiler、不导入候选、不写人工审核或发布记录。结构和格式通过不代表语义准确。

## 调用前冻结的评价标准

前三组沿用[4K 的正常/失败场景](AUDIT_SEMANTIC_CASES.md)。新增 allow-remaining-holdout 变体：来源和候选都写明 7 点共享预算、两个动作分别花 2 和 3 点、ALLOW_REMAINING，调查可选且结算不要求搜齐。两种真人选角都能在剩 2 点时推进，再揭晓指定真相。该变体在 1.11 提示冻结后加入，但仍使用原虚构故事模板，不代表足够广泛的独立测试集。

评价分别记录：旧有三种事实误报、预算反例和权限反例的关键问题是否漏报、剩余点数规则是否误用、来源是否支持具体意见、是否把推测说成事实，以及覆盖和输出完整性。任何有依据的额外意见也须保留；不按关键词或发现数量自动评分。预期答案和引擎轨迹放在 suite 的独立区，不进入任何模型消息。

`baseline` 不应被说成真相引用为空、缺少动作次数字段或必须多人接力调查。`unspendable-budget` 应识别剩 1 点无法用尽及预算与原来源不同；`role-dead-end` 应识别乙无权执行第二个动作和来源权限不一致。holdout 不应被套用 REQUIRE_EXHAUSTED。预期仅针对这些具体规则，不授予任意行动顺序、平衡或商业本整局通过结论。

## 工具及费用边界

入口 `backend/scripts/real_audit_semantic_smoke.py` 默认生成私有预览。整套上下文、候选、实际消息、模型快照、请求格式、预算、评价标准和引擎预期共同计算 suite_hash；执行必须显式带相同摘要，变化即拒绝。真实调用仍依赖既有用户授权、付费开关及显式 FOUR_SYNTHETIC_AUDITS 标记，不接受外部提示或商业材料路径。

最多四次 Audit，每样本一次，每次预占上限 ¥0.015，四次合计上限 ¥0.05。全部准备和总预算检查先于 SDK。独占且落盘的 suite claim 在任何请求之前创建，重复执行同摘要被拒绝；没有恢复、自动重试或换供应商。每次请求前重核保存的 suite 摘要及对应来源，然后先写 IN_FLIGHT 和预占。已知用量按原费率结算，未知结果保留预占并停止后续调用，超预占或用量异常同样停止；局部写盘失败保留 claim，不当作零费用重发。

合法格式的 BLOCKER 原样保留。四次响应完成只记 COLLECTED、SEMANTIC_REVIEW_REQUIRED，语义状态始终 UNREVIEWED；包含被本地校验拒绝的结果也必须逐项复核，不能把工具退出码 0 当作质量通过。stdout 只显示元数据，模型正文和原始输入留在私有文件中。

协议见[审核语义验收工具](../contracts/audit-semantic-smoke.md)。本批次已完成，本版本提示没有根据输出修改，也没有追加第二轮付费请求来消除失败。
