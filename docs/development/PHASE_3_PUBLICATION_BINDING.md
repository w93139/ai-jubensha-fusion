# 阶段 3D：人工确认、发布登记与固定版本开场

状态：本轮代码、离线检查与隔离浏览器验收完成，2026-09-06。承接[规则契约与真实小样本](PHASE_3_RULE_CONTRACT_REVIEW.md)。当前没有需要用户先试玩或补充的信息，已继续完成本工作包；用户的继续开发指令不等于对商业候选的人工批准。

## 本轮具体范围

复用 FastAPI / SQLAlchemy / Next.js，无新平台、依赖或模型调用。新增不可变人工批准、发布记录与开场会话绑定；仅在隔离 SQLite 测试和临时回环服务中创建测试批准，不迁移用户数据库、不发布真实商业剧本、不改原件或 `.env`。

人工确认必须绑定候选哈希、完整人工审核/处理历史、关联模型任务及报告、来源快照与校验版本。不能只看最近二十份报告或一条模型“通过”。所有人工 BLOCKER 需有明确排除理由，WARNING 需知悉或排除；模型报告保持独立，模型 BLOCKER/WARNING 由确认人逐项记录决定，不伪装成人工报告。至少具备一份完整五维人工报告及一份真实或离线验收替身的完整模型报告，自动流程没有人工批准权限。

确认后再单独登记发布，任何候选/报告/处理依据变化使原确认失效，旧请求不能用新依据重放。来源在确认/登记时重新核验，历史报告哈希与新的核验收据分开保存；时间戳不同不等于文件内容变了。所有写入通过同一候选锁串行检查，幂等键与唯一约束避免双重批准/发布。

## 运行边界

当前旧试玩是四至八人、固定两轮搜证与投票，读取平面私本；候选契约是二至八人、线性可变阶段、逐条权限。不能直接展平后套用旧游戏，否则会改变原规则。因此本轮增加独立的固定版本**开场预览**，复用原后台审核页面，不宣称完整玩法已经接线。

开场会话创建时固定用户、发布记录、候选版本/哈希、角色。只能读取开场公开资料和本角色开场已解锁资料，不返回其他角色私密、后续材料、系统真相或来源路径。新版本不改变旧会话；批准失效后不再新建会话，已有会话保留原授权只读视图。不添加阶段推进、投票、AI 对话或语音；明确返回 `runtime_ready=false`，完整玩法留到阶段 4。

旧会话及原有试玩不回填新绑定，新包不写入旧平面剧本表。旧管理员直接 PUBLISHED 入口已拒绝绕过新审核，旧编辑入口不能代替新包发布。旧全知游戏恢复入口不接新表。

每个候选版本只登记一份发布记录。已经发布的版本不能通过再次人工确认恢复失效状态，必须提交新的 `content_version` 并重新审核；完全相同的原请求仍可幂等重读。历史失败的模型任务保留在审核依据中，不覆盖后来成功报告；待完成或用量未知的调用继续阻断确认。

## 验收标准

- 未审核、报告不全、阻断未处理、模型决定缺失、篡改、过期确认、异步审核变更均不能登记有效发布。
- 重复请求只产生同一条记录；不同请求复用同键拒绝；事务回滚无半发布；ORM 禁止改删快照。
- 新建会话与确认失效共享候选锁；两个版本、两个用户和两个角色的初始权限互相隔离；旧会话不随新版本变化。
- 管理员能查看候选正文、模型建议、阻断原因，逐项确认后登记；玩家仅能打开安全开场预览。403/401、过期刷新、重复点击、390px 窄屏验证。
- 安全入口、前端组件/类型、预检、迁移离线上下行/ORM对比及生产构建。浏览器仅使用虚构资料，验收后关闭临时服务和空间。

真实 PostgreSQL 多进程恢复、商业内容人工校对、完整原剧本玩法和用户试玩仍需后续证据，不能以本轮 SQLite 和开场预览代替。
