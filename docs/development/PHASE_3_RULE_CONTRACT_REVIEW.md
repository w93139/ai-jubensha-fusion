1. 回归安全测试、前端组件和类型，核对开发文档与代码事实；保留现有未提交改动。
2. 独立检查模型得到的 JSON Schema/规则描述与服务端验收条件是否一致，尤其是阶段引用、初始私有知识、公开/私有披露及线索依赖。只补齐代码已有的规则表达，不创造剧本规则、不自动修复模型正文或放宽验证。

4. 所有模型输入改动都通过 Prompt/Schema/请求哈希冻结，旧文件与收据保留；新增诊断不回填旧任务。
5. 真实产物仅保存到仓库外私有 SQLite/来源目录；用户可查看结果的验收使用现有管理员路由和工作台。必要时在私有测试副本上启动临时回环服务，退出后清理本轮服务和浏览器空间。

独立审查发现两个可复现缺口：

- 模型收到的 JSON Schema 能约束类型和枚举，但 v3 Prompt 没有明确列出服务端跨字段规则。合法 Schema 输出仍可缺少角色初始私有知识，或把 PUBLIC 证据配成私有角色/披露规则；这些会被现有确定性校验拒绝。新增 v4 Prompt 明示这些既有约束，保留 v3 与原来的失败证据；材料不支持时要求 BLOCKED，不要求补写或提早释放内容。
- 原 smoke 只检查必要正确条目存在，漏掉额外越权副本和错误开场。合格候选若将开场改成系统真相、追加公开的角色私密事实或追加第二条真相，仍可能被旧断言记为通过。固定 fixture 的验收将改为完整对应两条私有事实、一条开场公开证据、唯一系统真相、准确开场/结算与阶段映射，保留无关生成 ID 和合法可选字段表示的自由。旧真实任务均已 BLOCKED，不存在需要追改的历史成功结论。

Audit 提示也存在同类的可复现遗漏：`introduction/settlement` 的 `target.id` 必须为 null，其余集合必须使用实际实体 ID；每个 finding.id 必须全报告唯一。错误报告能通过 JSON Schema，却被服务端拒绝。新增 Audit v2 Prompt 明示这些已有校验条件，保持五维覆盖、来源配对和无发布权限的边界，保留 v1 原文及历史哈希。

另外统一两处历史文档措辞：当前顺序是先验收私有候选/模型建议，再做人审发布门禁；自动 Audit 建议与人工报告独立保存。已确认当前 UI/API、只排队行为和显式 worker 设计一致，未发现需要产品经理补充的信息。
