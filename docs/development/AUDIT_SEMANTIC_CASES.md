# 审核语义验收样本 v1

这是一组独立预期，不是模型得分或发布批准。测试入口为 `backend/tests/fusion_security/test_audit_runtime.py`；私有输入在 `private-data/import-jobs/frozen-rule-plan-smoke/20260906-4k-offline-cases/`。商业原文未参与。

正常底稿沿用原固定合成 fixture，两个角色、两个阶段、两次动作成本 1 和 2、起始共享预算 3、动作每局一次、结尾引用已有真相。甲和乙分别作为唯一真人执行调查，不在一局里接力。基础正文、引用、奖励归属和结尾真相保持原烟测标准。

| 样本 | 唯一规则变化 | 引擎给出的预期 | 未来模型需核对的内容 |
| --- | --- | --- | --- |
| baseline | 无 | 两种选角均可完成记录的路线 | 不应声称 truth_ids 为空、缺 per_game_limit 或还需另一角色花点调查；仍可报告其他有来源支持的问题 |
| unspendable-budget | 起始预算 3→4 | 动作共花 3 点后剩 1 点且不能重做，无法推进 | 应指出此预算和一次动作组合无法满足 REQUIRE_EXHAUSTED，且预算与原来源不一致 |
| role-dead-end | 第二动作可用角色由甲乙→仅甲 | 甲可完成；乙做完第一动作后无权继续，无法用尽点数 | 应指出乙的权限及单真人可达问题，不得借甲的动作拼接证明乙可完成；也应核对来源的角色权限 |

两个反例仍通过结构及来源定位检查，说明结构有效不能当作语义正确。动作和预算保持有来源引用，所以模型意见必须定位实际目标并选择它自己的来源索引，不能补造或借用其他目标。

附加边界检查包括免费动作最多一次、AI 不可调查、备注伪造运行事实、观察值随真实候选编号变化、空真相列表拒绝、旧版本哈希保持、准备消息被篡改时零 SDK、合法 BLOCKER 不被删除。新规则和观察区始终 UNREVIEWED。

`expectations.json` 与引擎执行轨迹只用于独立检查，**不发送给被测模型**。模型收到实际候选、原来源及同一份程序规则，不能收到“这个案例应该报哪条问题”。固定样本也不应成为通过不断调提示记住答案的训练集；未来应补充独立留出样本，再在固定预算和每步一次请求下评估。

当前只完成可复现的程序事实核对，没有真实模型回答或语义得分。后续评审同时记录：具体事实误报、两个反例的关键问题漏报、来源是否支持意见、推测是否被说成事实，以及完整性/格式失败。不能按发现数量或是否出现某个关键词自动判定质量，也不能把“没有发现”直接当作通过。
