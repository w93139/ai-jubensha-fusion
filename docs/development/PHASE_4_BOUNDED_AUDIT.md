## 实现

新请求 `audit_mode=BOUNDED_TARGET_SOURCE_INDEXES` 与固定正文、完整规则准备稿和包 1.2 配套，任务/请求模型契约为 1.6。输出 `bounded-audit-draft/1.0`：摘要最多 240 字符、每条发现说明最多 160 字符、最多 10 条发现，必须显式标记 COMPLETE 或 INCOMPLETE。五维覆盖、非空且属于目标自己的来源编号、旧领域报告校验继续保留。

COMPLETE 仅表示模型自称本次审核已完整输出，并不是“无问题”或批准。提示要求：超过发现容量、文字限制无法表达全部问题、任一维度未查完，都须 INCOMPLETE；不得少报问题来凑长度。服务器拒绝 INCOMPLETE、缺少状态、超长、无效引用、额外字段，成功才装配为原 `script-audit/1.1`。该边界不能证明模型没有遗漏，也不保证每次回复都能放进 token 上限；真正的大报告仍需后续有边界的分项审核。

工作台新建“固定规则和正文，只检查内容”任务时选择 1.6；旧 1.5/1.4 的请求、提示与快照不升级。HTTP 只排队，worker 要求显式参数，详见[契约](../contracts/bounded-audit.md)。本轮没有改变输出 token 上限、价格配置、供应商或失败任务重试规则。

新收据可包含 `response_finish`：只保存 stop、length、content_filter、tool_calls、function_call、OTHER 或 null。未知原始值统一 OTHER；缺失/未返回为 null。旧收据不补字段、hash 不改写。带新字段的成功收据必须为 stop；前端为长度、过滤、未知原因提供固定中文解释，不显示任意供应商原文。

真实运行后进一步加入 `AUDIT_BOUNDED_SCHEMA_INVALID` 诊断：最多 10 个固定字段路径，覆盖状态、摘要、覆盖范围、发现说明、目标和引用编号。未知字段名只定位到获准父节点，位置只允许有界数字，不回传输入值、模型文本、目标 ID 或 Pydantic 原始报错。该诊断已离线与模拟持久链验证，但本轮没有再付费验证。
