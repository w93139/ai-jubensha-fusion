# M2：讨论驱动的调查建议接线

2026-09-07。公共讨论后的第二个工程子项。新增可操作页面和持久模型请求；仍不代表《孽岛疑云》完整角色互动或整局已通过。

## 新增体验

在 `/play/package-play` 保存公开发言后，选择 AI 角色并点击“征求调查建议”。AI 选择地点及可公开依据，程序生成固定短句；可展开查看引用，保留事实、角色说法、推测及发言者。建议不会扣调查点、公开私卡、执行搜证或统计投票。

角色能根据自己的已解锁材料（含 KEEP_PRIVATE）和全部已保存公共讨论作选择。角色材料中明确写出的当前任务和目标原样进入输入；不从角色名称推导或补编目标。未解锁材料、别人的私本、后台真相和来源路径不进入输入。来源仍由已绑定包中的材料及来源引用追溯，本轮没有创建新的商业目标文本或把编辑规则标为批准。

目标当前仍是角色材料内的原文，不是新增的结构化个人目标/计分系统。实际商业本各阶段目标是否已完整进入获准候选，需要后续逐项核对；本轮虚构夹具不能替代这项工作。

## 避免补编台词的实现选择

上一轮真实模型曾输出没有依据的理由。因此本协议只允许 `action_id` 和至多三条 `public_basis`，不接受自由台词、私人解释或额外字段。程序显示“我建议先考虑……”，并展示已存在的公开引用。私人信息可以影响选择，但其正文和引用编号不能直接出现在公开依据中。

这保证的是输出渠道和引用权限，不是模型选择一定合理。引用存在不证明它支持这次选择；固定短句也不能算自然角色对白已完成。自由对话、情绪与更自然的解释仍待独立验证。

当前建议范围为 AI 和真人都能看到且当时可执行的调查动作交集；避免建议暴露另一个角色独占的隐藏地点。尚不代表已经适配原本全部集体调查或角色独占行动规则。

## 接线与持久性

- 使用既有 FastAPI、SQLAlchemy 事务、试玩事件表和 Next.js 页面，无新增表或数据库迁移。
- 显式 `package-investigation-command/1.0` 的 PROPOSE 由新 `/proposals` 入口处理；旧 `/ask` 的材料模型提示、初始 binding 和旧事件保持原样。
- 首次提议请求冻结 `package-proposal-model/1.0` 元数据。沿用原局供应商、模型、价格和参数；不跨渠道回退，不自动增加预算。首次提议起仅新追加事件使用 `package-text-play-event/1.2`。
- 与旧材料问答共用单局预算、30 次请求上限、一次在途请求和统一 revision。完整消息及动态输出 schema 都计入预占上界；先提交预占，再单次调用，等待网络时无行锁。thinking 保持 disabled，要求正常 stop。
- 新发言、调查、推进或失效发布使旧结果失效；仍记录已知费用或未知预占，不发布提议。未知/过期请求不自动重发。
- 公开提议和每次请求状态均存档；页面重进从 GET 找回未结请求的角色、原请求键和 revision，点击“检查上次建议结果”才查询/结束该请求，不新发模型调用。每次结果按自己的请求核对，避免把另一条 AI 请求的成功误认为本次成功。
- SDK 生命周期和结束原因/用量检查复用旧适配器，输出解析使用新协议；旧材料输出字段与请求字节保持。

旧代码不能读取含新 1.2 事件的会话，不可通过删除历史回滚。GET 和历史重放不依赖当前模型配置一致；配置变化只阻止新调用，不隐藏已获得内容。
