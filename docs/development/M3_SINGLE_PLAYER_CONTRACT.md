# M3 单人流程收口（2026-09-09）

用户在路线复核后要求重新梳理修复。本次把已确认的单人方向落实为一份操作说明、五阶段目标与当前可用议题；案件事实、证据、原始包和旧存档不重写。

完成标准：服务端按阶段、玩家已见材料、角色已知材料开放固定议题；每角色每议题初问及最多两项固定追问，公私聊共用次数。自由公开发言只记录玩家说法，不能作为绕过议题的 AI 请求。初问保存与 AI 请求分开落账，使用冻结原请求核对，未知结果不重发。失败或不可用时由玩家明确选取有来源的固定答复，不冒充模型成功。私聊不会公开给全体。旧请求仍可原键恢复，内容目录丢失时关闭新交流，保留记录。

范围：single-player 内容校验/投影、topic 严格命令与事件、现有对白上下文收窄、前端统一议题交互、私有改编稿与来源核对、PRD 状态。无需新增模型框架、LiteLLM、TTS、数据库迁移、改故事真相或进入 M4。

风险：来源有效不能自动证明语义正确；采用人工来源核对和有限真实模型样本分别验证。旧事件重放不能依赖可变目录，新增规则只影响新命令。

验证：专用 fusion_security 全套（禁网虚构数据）；dev_preflight 及其 16 项自测；前端 tests/typecheck/lint；隔离构建；独立只读复核；独立验收局跑当前议题、越权/重复/失败路径。部署前备份 SQLite 并比较旧行摘要；私有 GitHub 导出白名单后验证代码与版本标签。

## 实际交付

- PRD 0.7。开场和进入游戏共用单人操作稿，五阶段目标/结束说明；两轮八个有限议题，十三个角色初问入口及相应追问，来源与条件逐项核对。
- 新问题绑定本人当前材料、披露边界与原请求；同角色同议题每个问题一次，公私聊共用。公开自述只保存观点，不绕过议题调用 AI。初问提交后待发预览清空，答复原位显示，追问保留此前答复。
- 模型失败、不可用或明确停止等待后，玩家可选有源短答继续；失败费用和原请求保留。未知结果先核对，不能暗中重发或将短答记为模型成功。
- 实际抽样发现并针对性修复：回忆所需姓名遗漏、转述变亲历、不确定性升级、时间地点拼接、角色期待变他人承诺。正常读报的表达获得严格文献例外，仍不允许冒充历史事件目击。
