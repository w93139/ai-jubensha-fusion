## 1. 产品目标与边界

让一名真人与四名 AI 角色完成《孽岛疑云》：读本、交流、调查、触发回忆、提交答卷、查看得分与结局，并能保存继续。重点解决完整游玩、角色知识隔离，以及阅读时随时翻阅任务和关键信息的问题。

- **已确认**：保留 FastAPI / Next.js / PostgreSQL 基座；M3 本机验收使用独立 SQLite 持久存档。按已确认规则版本运行，不改写原商业材料、不自动升级旧局。
- **已确认**：M3 固定真人唐小姐，其余四席为 AI；M4 验证五种真人选角，仍是每局一名真人，不是五人联机。
- **已确认**：豆包语音输入（ASR）作为用户新增需求纳入 M3；AI 发言先逐行文字显示，TTS 朗读暂不加入最小 MVP。
- **本轮新增**：M3 固定主持三级提示，按当前阶段按需揭示。**后续范围**：TTS、打断、更广泛的主持引导及正式部署。任意剧本自动导入和五真人联机没有列入已确认的第一版范围。

## 2. 玩家流程与开发大纲

选择故事与角色 → 阅读本人开场与任务 → 一次开始进入或恢复游戏 → 按阶段阅读、公开发言／角色提问／规则允许的私聊 → 批量选点并由其余角色自动接手 → 获得线索和条件回忆 → 推进前选择复盘或继续 → 手动推进并整理阶段摘记 → 指认、信任票及私密答卷 → 五席封卷 → 分项评分与结局。

- **验收条件**：严格 JSON Schema、固定模型、关闭重试/回退、人民币/美元换算与自定义费率、并发预算、跨小时/重启恢复、私本日志隔离。该源码会话预算默认 TTL 为 3600 秒；未知价格可能跳过请求费用预占，不能直接替代现有整局硬限制。

- **成本判断**：网关不自动降低供应商单价，还增加部署与维护成本；未实测前不承诺节省比例。
