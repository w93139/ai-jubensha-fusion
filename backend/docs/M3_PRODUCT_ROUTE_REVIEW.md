# 单人玩法路线回溯与收口建议

2026-09-09｜审查稿。区分用户已确认约束、当前实现和下一步建议；不批准改写原作真相，不代表玩法已验收。

## 结论

一名真人与四个 AI 完成推理游戏有实现基础：已有真实整局完成、角色权限、调查、回忆、投票、结算与恢复记录。但当前版本尚不能称为稳定、自然、无需开发者解释的单人剧本杀。

目标没有变，体验实现出现了偏移：玩家面对了排版核对、原文问答、逐段提问等开发工具；阶段“能推进”先于阶段“知道为什么推进”。修正重点是单人交互剧本和每阶段约束，不是增加 Agent 数量、换框架或继续堆问答按钮。

## 当前偏移与影响

1. **把校对工具带进玩家页面。** `PlayText` 的原始排版开关会在正文、回忆、收藏中重复展示 OCR 文字。来源核验应留在编辑工作中；玩家需要一个已整理的版本。真实线索图片仍是游戏内容，应保留。
2. **把资料阅读做成碎片问答。** 每段“就这段内容提问”、每条“继续追问”会暗示任何文字都值得询问，分散当前目标。完整玩法还同时显示早期“原文材料问答”和后来的自然角色交流，两条通道意义不同却挤在一起。
3. **规则可执行，但阶段体验契约不完整。** 当前可选择动作、推进和结算，不等于玩家知道本轮要调查什么、何时足够、哪些疑点该留到下一轮。不能靠用户不断猜关键词或开发者在旁边教操作。
4. **用输出校验承担了过多内容设计责任。** 结构、来源 ID 和长串原卡复制检查能拒绝明显错误，不能证明台词忠实、必讲完整、推测保留不确定性或回答真正回应问题。既有真实失败记录已经说明这一点。
5. **限制开放程度还没有形成议题规则。** 当前 `package_request_scope.py` 明确只识别部分外部任务与元信息索取，不是任意跑题语义分类器。1000字和轮数是输入/费用限制，不等于玩法边界。去掉按钮只是入口收口，尚未实现阶段议题白名单。
6. **旧操作说明与新适配并存。** 已有“本局操作说明”明确真人选址，但冻结材料中的集体调查条款仍在阅读正文中。需要整理为一份一致的单人操作稿，避免玩家自行判断哪份规则优先。

## 是否需要改写

**建议保留故事事实与核心推理，改编交互和主持执行稿。** 线下本依赖多人主动交谈、临场表演、协商和主持人判断；改成单人后，这些责任必须明确分配给系统与 AI。

| 内容层 | 建议处理 | 约束 |
| --- | --- | --- |
| 案件真相、时间线、关键人物关系、证据事实、已采用版本的目标含义 | 保留并继续做来源校对 | 不为了让模型回答顺畅而编造事实或修改真凶 |
| 玩家阅读稿 | 去除 OCR 痕迹与重复工具内容，按阶段整理；必要时提炼任务提示 | 不把后续回忆混进开场，不把“角色认为”改成客观事实；删减关键叙事须逐项核对 |
| 五人协商与线下操作说明 | 改写为明确的单人操作稿 | 延续用户已确认的真人选址、文字私聊与独立终局票；新增规则须标为适配决定 |
| AI 必讲线索 | 已获且必须讲的内容使用有源、完整的固定台词；AI可承担有限表达 | 只保证必须送达，不把可隐瞒内容全部公开；仍标注为角色说法 |
| AI 自由交流 | 建议围绕当前议题、当前对象和授权线索生成有限回应 | 不能新增经历、决定真相、替玩家推理答卷或改变规则 |
| 卡住时的帮助 | 当前三级提示保留；下一步将提示绑定更具体的当前问题和未完成行动 | 不自动弹答案；第三档仅解当前卡点并记录辅助，不能伪造“玩家已推理出” |

这不要求重写成一部新故事，也不能承诺任意五人本经 OCR 后就自动适合单人游玩。每本都需要一份经过审阅的单人适配表。

## 建议的单人交互契约（尚未实现/确认的新部分）

每个阶段先填写下表，再做界面与提示词。建议第一轮先做少量可验证议题，例如2–4个；数量只是初稿建议，不是已定商业限制。

| 字段 | 必须明确的内容 |
| --- | --- |
| 玩家目标 | 这一环节正在查哪件事；哪些疑问暂时没有足够材料，不需要现在解决 |
| 可采取行动 | 当前合法地点、可交流对象、议题和提交项；保留玩家的顺序、怀疑与公开/保密选择 |
| 角色责任 | 每个 AI 已知事实、动机、必须说的内容、可选择说的内容、必须保密内容 |
| 交流边界 | 建议先选对象与议题，再允许与该议题有关的简短追问；选项不直接泄露答案；自由文本是否保留及追问次数待玩法样板验证 |
| 有效后果 | 这次交流带来了哪条新说法、澄清或选择；不能只是循环反问，不能假称真人已经相信 |
| 信息门槛 | 获得材料、实际听见台词、允许公开分别记录；不能因模型读过、按钮被点过就算玩家获知 |
| 阶段结束 | 必需系统事件已完成，满足规则或玩家明确结束调查；不强制猜对才推进，保留误判与最终评分的意义 |
| 卡住恢复 | 缺少必讲、遗漏调查、误解规则分别给出预设帮助；可选隐瞒不靠强制自曝来解锁；失败/超时保留记录，不无限重新生成 |

建议的体验顺序：阅读本轮任务 → 听取必须角色说明 → 自主选择地点并获得线索 → 围绕当前疑点交流 → 整理自己的判断 → 明确进入下一阶段。实际发布顺序以对应剧本和已确认的适配规则为准。

## Agent 与系统分工

| 部分 | 负责 | 不应负责 |
| --- | --- | --- |
| 确定性规则与存档 | 阶段、动作资格、调查扣点、发卡、封卷、已确认评分、事件与费用恢复 | 临时编造剧情或因模型一句话修改真相 |
| 主持流程 | 当前任务、节奏、必讲调度、预设提示与卡住路径；目前只有其中一部分实现 | 依赖自由生成临场决定新规则或随时告诉玩家全局答案 |
| 四个角色上下文 | 各自知识、目标、有限表达与独立选择 | 共享全本、查看他人私本/封卷、永远配合真人或替真人完成推理 |
| 玩家 | 决定调查、提问重点、公开或隐瞒自己的信息、形成判断和提交最终答案 | 操作每条模型请求、原文校对、替系统补齐必需的角色信息 |

沿用当前 FastAPI / Next.js / 数据库与事件方案即可。多个角色使用隔离上下文，不要求增加四套 Agent 框架或四把 API Key。LiteLLM 仍是未来运营候选，不解决剧本改编、角色职责和推理路线问题；本次无需重新配置文字 API。

## 接下来如何验证“真的能玩”

建议先完成唐小姐的一个完整调查环节样板，再沿同一契约整理后续环节。明确交付应是可玩的环节与单人适配表，而非新增工具清单。

- 普通路径：玩家不看开发说明，也知道当前目标、能做什么和如何继续。
- 没有问中关键词：必需线索有来源明确的送达路径；可选回忆仍按规则触发，不无条件送齐。
- 角色隐瞒：AI 保留合理利益冲突，玩家仍有证据路径，不因一次拒绝永远卡住。
- 早结束/误判：进度可保存、继续与结算；不偷偷退点、改真相或补成正确答案。
- 回答失败：已授予信息与草稿保留；必要剧情不依赖不断重试模型才出现。
- 服务与终局：调查能继续不代表四席封卷始终有可用模型额度；需专项验证预算临界、模型不可用时的保存与恢复，不擅自代投或填答。
- 帮助与恢复：三级提示不越阶段；刷新、私聊切换和未知结果核对不串信息、不重复计费。

**验收判据建议：**阶段内必需信息均在合法条件下实际送达；不出现未来/他人私密泄露；同一问题不会无限反问；玩家的调查、保密和最终判断仍有意义。上述是下一步需证明的体验条件，不是本轮已经全部通过的结论。时长、延迟目标和议题数量通过样板试玩再确定，暂不填写虚假百分比。

## 本轮范围与下一步

本轮仅落实用户明确的页面收口，并审查路线：去掉原始排版、逐段/逐条提问入口，在完整玩法中收起旧原文问答的新建入口；收藏、真实图片、任务/回忆、集中角色交流与原记录恢复继续保留。单人议题契约和完整操作稿仍是可审阅建议，未改写商业原稿或冻结游戏状态。

当前是 **M3 玩法收口与单人适配复核**。下一步建议交付第一调查环节的目标、角色职责、议题/行动和卡住路径，以及对应可玩样板；先证明该环节可独立游玩，再扩展整局，随后做 M4 五种真人选角。建议开发思考强度极高，因为信息分配与角色动机比增加按钮更影响推理是否成立。
