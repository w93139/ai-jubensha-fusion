# M3 首页流程交付与验收

本轮范围是将已接受的单人文字游戏接回首页。首页、旧剧本中心与旧大厅使用同一玩家入口，最近一局显示继续游戏或查看结局；全部游戏在“我的记录”分页查看，开始新游戏进入现有选故事/角色与开场流程。

## 产品流程与存储

- 首页 → 选择角色 → 阅读开场 → 一次开始进入游戏。创建保持原角色/版本绑定和幂等，不把导航视为开局。
- 游戏 → 返回首页 → 继续游戏：原 play_id、阶段、线索、回忆与事件保持；首页只查询已开始游戏，不把未开始的阅读记录当游戏局。
- 我的记录：每页12条，可加载更多；已结束显示查看结局，未结束显示继续游戏。排序依据最近保存进度，单纯浏览不会更新记录时间。
- 首页不展示内部版本、成本、私本或答案；最近一局可能已结束，其他未结束局可在全部记录继续。
- 导航只有首页、开始新游戏、我的记录；头像打开当前账号信息。账号编辑、密码设置、旧编剧中心不属于本轮交付。

## 后端与前端边界

新增只读 GET `/api/fusion/package-play-library?offset=0&limit=20`，offset非负、limit1–50；账号由认证依赖确定。先过滤owner再分页并校验回放，只返回游戏id、开场id、标题、角色名、友好阶段、结算标志、revision、最近进度时间；不返回正文/真相/费用。所有响应no-store，包括鉴权中间件提前返回的失败。旧按opening查询接口不变。

前端以账号id重挂载并监测token变更；失效立即清空记录、取消请求，晚响应不能回填。失败与空记录分开，记录/目录各可重试；重复点击分页不并发发送。继续链接只携带已校验游戏id，不调用创建或模型。

## 用户复验列表

1. 打开首页，能看到最近一局和可玩的故事，没有“获取脚本列表失败”或内部M3名称。
2. 点击继续游戏：进入之前保存的角色和阶段；已结算记录显示查看结局。
3. 从游戏底部返回首页，再点击继续游戏或刷新：阶段和已有资料保留，没有新生成一局。
4. 开始新游戏选择唐小姐，阅读开场后只点一次开始，直接进入游戏。选择其他角色的完整单人适配属于M4，不能用已有选择控件当五角色验收通过。
5. 打开我的记录，加载更多：旧局均可找到，不重复；返回首页入口有效。
6. 手机宽度下展开/关闭导航、点击记录与返回：首页无横向溢出，关闭按钮不被遮罩挡住。实体手机软键盘仍需单独验证。

## 验证证据

前端全量483项及末次相关208项通过；后端2743项、预检16项通过；类型、lint（0错误/33既有警告）、隔离生产构建及独立只读复核通过。真实页面使用单独QA局验证创建、推进、返回、继续和刷新；实际库分页先读12条再补足21条，无重复。最后结果、截图、旧数据摘要与本机部署记录位于私有 home-flow-20260909 交付目录；验收不等于正式发布。

## 下一阶段

当前是M3首页收尾；剩余真实豆包ASR、实体手机输入和已登记模型语义谨慎项不因首页通过而消失。首页认可后集中做这些专项并记录通过/待修，再推进M4。

M4是五种真人选角适配：先做一个新增角色的阶段目标、已知/可说范围、回忆、问题与评分，验证完整整局，再覆盖其余角色。现有规则引擎和页面可以复用，所以基础搭建量未必超过M3；角色语义、权限组合及逐角色验收更难。交付角色适配表和可玩样板，以用户完整走通、必需信息送达、无越权剧透和正确结算为标准。

后续普通体验问题可以持续迭代；进度损坏、越权泄露、无法继续游戏需优先修复。建议首页常规开发思考强度高，M4角色/语义/权限为极高；不声称已更改会话或游戏模型设置。
