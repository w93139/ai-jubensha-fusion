# M3 单人交流契约

用户确认路线复核后的修复方向。现阶段固定真人唐小姐，目标是一人完成调查并与四名有独立信息的角色交流。

## 玩家流程

阅读当前目标和单份操作说明 → 自选调查地点 → 获得真实线索并接收必须转述 → 选择当前议题与角色 → 初问及最多两项固定追问 → 必要时询问主持人 → 自行决定推进 → 指认、信任票和私密答卷。

五阶段分别显示目标、操作和结束说明。阅读/调查结束仍由玩家选择，议题与答案不作为强制通关条件。不会以‘看过’标记‘已理解’，未知判断可以保留。顶部资料与任务入口继续支持原位查阅。

开场预览与正式进入文字试玩使用同一份操作说明。开场仍先按当前角色和初始阶段过滤材料；操作稿不会将后续议题、私本、回忆或主持答案带入开场。指定必须适配的绑定在目录缺失时不返回矛盾的旧多人说明，原开场存档和其他未适配剧本保持原机制。

## 交流规则

- 两轮共八个核心议题；标题与问题只在当前阶段、必要玩家材料已见、所选角色确有相关材料时开放。
- 每个角色每个议题只能初问一次、两个预设方向各追问一次，公私聊共享次数；初问得到可用答复后才开放追问。
- 公开自述仅记录玩家的说法。新单人局的材料问答、任意自述对应 AI 回应、旧 AI 搜证投票入口不能绕过议题限制。
- AI 使用本人已知的相关可转述材料和本人保密策略。材料引用不是语义正确证明；保留角色不确定、传闻归属和可隐瞒内容，不强迫坦白所有秘密。
- 私聊使用同一有限议题与上下文气泡，只有通话双方听到；不会当成全员听到。主持提示及议题标题不直接授予回忆。

## 故障与恢复

规范问题先存一次，再按冻结请求发起一次模型回答；请求前预占、结果后记账沿用既有协议。已知请求只可原键核对，未知结果不生成新键重试。

模型不可用、预算不够、失败或已停止等待未取得可用结果时，玩家可明确选择有来源的固定答复。它是预设角色短答，不是成功模型结果，也不会再调用模型。未派发问题因其他操作使原 revision 过期时，同样可用固定答复继续。已经派发而仍等待的请求须先核对，不能抢先发布固定答复。旧记录与费用不回填。

固定答复与模型答复都绑定实际消息 ID，使追问保留前答；公开及私聊历史只选当前议题、角色、渠道。目录移除后已有冻结记录可读，不能退回开放 AI。

## 有源答复检查

真实抽样暴露了回忆所需人名遗漏、公共调查材料变亲历、别人转述并入自己经历，以及原文‘似乎’被说成事实。新议题可显式冻结 `topic-answer-check/1.0`：初问必达词、指定转述片段、公共来源归属、须保留的限定词及保守确定性检查。约束随请求进入角色策略区，服务器在写入实际发言前验证。

只影响带该显式契约的新问题。旧 OK、失败与未知收据不重新判定或覆盖；一个来源引用合法并不等于语义正确。有限检测可能保守拒绝合法表达，也不能识别所有语言变体。被拒绝的结果正常记账但不进入公开/私聊发言，玩家可主动选择经来源核对的固定答复继续，不自动再调用模型。

对于已审核并明确列入 `public_document_basis` 的已获文献，允许描述读到报纸、头条或记载；仍不允许把文献报道的历史事件写成本人目击，其他公共线索也不会获得此例外。例外随新问题冻结，旧问题没有该字段则保持原结果。该修复针对实际读报误拒，不能作为一般语义判真或引用精度保证。

## 实现与状态

服务端私有内容 `single-player-content/1.0`，玩家投影 `package-single-player/1.0`，严格命令 `package-topic-command/1.0`。角色原知识、证据、来源、案件真相和旧事件不改写；新的适配操作稿只替换精确指定的玩法说明投影。商业内容只在本机私有目录，GitHub 仅保存通用代码和虚构测试。

当前为 M3 开发验收候选。离线通过、付费模型抽样和用户完整体验分别记录，不以流程可执行代表全部语义准确。真实 ASR 与 M4 五种真人角色尚未完成。
