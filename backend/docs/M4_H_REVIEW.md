## 范围与验收依据

- H 使用独立 `single-player-content/1.0`，覆盖五阶段、9 个调查议题、14 个答者组合和 42 条有源短答。真人自己的经历、目的、回忆和终局题不借用其他角色身份。
- 只为新候选设置新的 `content_version`，所有事实、证据、机制、判分和来源列表与前一候选逐项相同。新候选哈希通过 `content_hash` 计算，不回填旧记录。
- `package_h_registration.register_h_content` 返回新的外层注册字典，使用仓库现有的 `package_hash → character_id → catalogue` 双重绑定，保留旧映射对象，拒绝覆盖或混用其他角色、来源和包内容。它不写数据库、不创建发布记录、不启动服务。
- 私有伴随注册脚本验证 H 目录和主持配置后返回服务参数。主持配置保持其他 AI 必述链，真人 H 的必述只提示义务，不能自动代说。
- 新增泛化注册测试留在仓库；商业本 JSON、原文审查、实际 H 整局测试和输出全部留在仓库外私有目录。

1. 核对目录结构、逐项来源与文本摘要、替换范围、全部答者与问法；独立审查 42 条兜底短答，因为显式兜底不再次经过模型答案校验。
2. 隔离 SQLite 与模拟 SDK 验证 H 开场、五阶段、议题门槛、公私聊共用次数、冻结请求、失败后显式兜底、回忆触发、必述不代说、四 AI 封卷和结算重读。另验证提前结束调查路径。禁止网络和读取运行数据库。
3. 使用 `backend/scripts/test_fusion_security.py` 执行用户指定五个模块及完整离线套件；该入口关闭 `.env`、插件自动加载和网络，并隔离旧父级 `conftest.py`。
4. 完成仓库要求的前端八套、TypeScript、开发预检及其自测、`git diff --check`，并校验旧文件摘要保持。
